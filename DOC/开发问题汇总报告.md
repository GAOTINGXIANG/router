# LAN8720 DHCP 服务器 —— 开发问题汇总报告

> 目标:ESP32-WROOM-32 + LAN8720,作为 DHCP 服务器为接入设备分配 IP
> 环境:ESP-IDF v6.0.2
> 状态:✅ 已完成,运行正常

## 最终运行日志(验证通过)

```
ethernet: Ethernet link up
ethernet: DHCP server started, serving 192.168.4.0/24
esp_netif_lwip: DHCP server assigned IP to a client, IP is: 192.168.4.2
```

接入设备成功获得 `192.168.4.2`。整个开发过程中共遇到 **3 个问题**,逐一记录如下。

---

## 问题 1:编译报错 —— `IP4_ADDR` 参数个数错误

### 现象
```
'IP4_ADDR' undeclared (first use in this function)
macro 'IP4_ADDR' requires 5 arguments, but only 2 given
宏 "LWIP_MAKEU32" 调用中的参数太多
```

### 根因
代码里用宏拼接 IP 并传给 `IP4_ADDR`:

```c
#define ETH_STATIC_IP  192, 168, 4, 1
IP4_ADDR(&ip_info.ip, ETH_STATIC_IP);   // 报错
```

C 预处理器**先按实参个数匹配、后展开宏**:`IP4_ADDR` 只收到 2 个实参(`&ip_info.ip` 和 `ETH_STATIC_IP`),等 `ETH_STATIC_IP` 展开成 `192,168,4,1` 时,逗号分裂已经太迟,导致 `LWIP_MAKEU32` 收到的参数数量错乱。

### 解决
改用 ESP-IDF 惯用的 `ESP_IP4TOADDR` 结构体初始化(该宏由 `esp_netif.h` 自动引入),并删除多值 `#define` 和多余的 `lwip/ip4_addr.h` 头文件:

```c
esp_netif_ip_info_t ip_info = {
    .ip      = { .addr = ESP_IP4TOADDR(192, 168, 4, 1) },
    .netmask = { .addr = ESP_IP4TOADDR(255, 255, 255, 0) },
    .gw      = { .addr = ESP_IP4TOADDR(192, 168, 4, 1) },
};
```

## 问题 2:运行崩溃 —— PHY 初始化失败(`power up timeout`)

### 现象
```
E eth_phy_802_3: esp_eth_phy_802_3_pwrctl(305): power up timeout
E eth_phy_802_3: esp_eth_phy_802_3_basic_phy_init(494): power control failed
E lan87xx: lan87xx_init(340): failed to init PHY
E esp_eth: esp_eth_driver_install(251): init phy failed
```

### 根因
硬编码了 `phy_cfg.phy_addr = 0`,但 LAN8720 模块的**实际 PHY 地址是 1**(PHYAD0 上拉)。

驱动向地址 0 的 BMCR 寄存器写「退出掉电」后,连续 100ms 读回仍是 0xFFFF(无设备应答,0xFFFF 的 bit11 恰好为 1),于是判定 `power up timeout`。

### 解决
改为**地址自动探测**,让驱动扫描 0~31 找 PHY:

```c
phy_cfg.phy_addr = ESP_ETH_PHY_ADDR_AUTO;   // -1
```

> 说明:PHY 地址由 `PHYAD0` 引脚上下拉决定,0/1 都可能,不同模块不同。自动探测最稳妥。

---

## 问题 3:运行崩溃 —— DHCP 服务器启动失败(`DHCPS_START_FAILED`)

### 现象
```
I ethernet: Ethernet link up
E esp_netif_lwip: DHCP server cannot be started
ESP_ERROR_CHECK failed: esp_err_t 0x500d (ESP_ERR_ESP_NETIF_DHCPS_START_FAILED)
```

### 根因(决定性)
默认 `ESP_NETIF_DEFAULT_ETH()` 创建的是 **DHCP 客户端**网卡(flags = `ESP_NETIF_DHCP_CLIENT`)。SDK 在创建 netif 时,**只有带 `ESP_NETIF_DHCP_SERVER` 标志才会分配 `dhcps` 对象**:

```c
// esp_netif_new() 内部
if (flags & ESP_NETIF_DHCP_SERVER) {
    esp_netif->dhcps = dhcps_new();   // 默认 ETH 网卡没走这里
}
```

因此 `esp_netif->dhcps == NULL`,`esp_netif_dhcps_start()` 内部调用 `dhcps_start(NULL, ...)` 返回 `ERR_ARG`,映射为 `DHCPS_START_FAILED`。

### 解决
1. **创建 netif 时声明为 DHCP 服务器**(把默认 flags 里的 `DHCP_CLIENT` 换成 `DHCP_SERVER`):

```c
esp_netif_inherent_config_t base_cfg = ESP_NETIF_INHERENT_DEFAULT_ETH();
base_cfg.flags = (esp_netif_flags_t)(ESP_NETIF_IPV4_ONLY_FLAGS(ESP_NETIF_DHCP_SERVER) |
                                     ESP_NETIF_DEFAULT_ARP_FLAGS |
                                     ESP_NETIF_FLAG_EVENT_IP_MODIFIED |
                                     ESP_NETIF_DEFAULT_IPV6_AUTOCONFIG_FLAGS);
esp_netif_config_t netif_cfg = { .base = &base_cfg, .stack = ESP_NETIF_NETSTACK_DEFAULT_ETH };
```

2. **初始化顺序调整**:`dhcpc_stop` 改为 `dhcps_stop`(把服务器状态置为 STOPPED,才能 `set_ip_info`),再设静态 IP。

3. **事件回调容错**:链路通时 `dhcps_start`、断时 `dhcps_stop`,但把 `ALREADY_STARTED` / `ALREADY_STOPPED` 当作正常情况,不再 `abort()`。

## 附:开发中出现的两个「非问题」现象(说明)

| 现象 | 说明 |
| --- | --- |
| 日志从 `ethernet attached` 到 `init done` 停顿约 4 秒 | 正常。驱动首次链路检测等待 PHY 自动协商,超时 `autonego_timeout_ms = 4000ms`;未插网线时等满 4s,插线后明显变短 |
| `spi_flash: Detected size(4096k) larger than the size in the binary image header(2048k)` | 提示,非错误。板子实际 Flash 4MB,但固件按 2MB 分区表生成;暂不影响本功能,后续程序变大需在 menuconfig 里改 Flash 为 4MB |

---

## 经验总结

1. **C 宏参数个数在展开前就固定** —— 不要用会展开成多个逗号分隔值的宏去填充另一个函数式宏的单个参数。
2. **PHY 地址不要想当然** —— 用 `ESP_ETH_PHY_ADDR_AUTO` 自动探测,省去 0/1 之争。
3. **`ESP_NETIF_DEFAULT_ETH()` 默认是 DHCP 客户端** —— 做 DHCP 服务器必须显式声明 `ESP_NETIF_DHCP_SERVER`,否则 `dhcps` 对象根本不会被分配。
4. **善用 SDK 源码定位问题** —— 三次问题都是通过读 ESP-IDF 源码(`esp_eth_phy_802_3.c`、`esp_netif_lwip.c`、`dhcpserver.c`)确认了确切的失败条件,而非猜测。
